# Project Showcases

**Projects** are structured pages for the things you build — apps, libraries, services, experiments. Peermeld's pitch: *"Publish your projects, tech stack, and build logs"* — clean layouts with names, logos, screenshots and live links, ready in seconds.

## Anatomy of a project

| Field           | Purpose                                        | Discovery tip                                  |
| --------------- | ---------------------------------------------- | ---------------------------------------------- |
| **Name**        | The product's identity                         | A real, brandable name — not "my-app"          |
| **Logo**        | Visual anchor in cards and lists               | Even a simple mark beats none                  |
| **Tagline**     | One-line description                           | *"Realtime weather telemetry service"* — what, not how |
| **Tech stack**  | Tags like React, Vite, Node, PostgreSQL        | Tags are how people *find* projects — add 3–6  |
| **Live link**   | The working product                            | A dead link is worse than none — keep it green |
| **Screenshots** | Visual proof                                   | Show the UI in 1–3 crisp shots                 |
| **Status**      | **Live** or **In Progress**, with dates        | Both are respected; in-progress = building in public |
| **Build logs**  | Attached markdown write-ups                    | See [Build Logs](./build-logs)                 |

Real project cards from Peermeld's own showcase style: *ConnectSphere — SaaS professional network directory (React, Node, PostgreSQL) · Live*, *Frostline Analytics — Realtime weather telemetry service (Next.js, Tailwind v4, Radar) · Live*, *Peermeld Blueprint — Blueprint style portfolio builder (Vite, React Start, Bun) · In Progress*.

## Create a project

<Steps>
<Step>

### New Project
From **My Projects**, hit **New Project**. Give it a name, tagline and logo.

</Step>
<Step>

### Tag your stack
Add the technologies — React, TypeScript, Node, Postgres… Stack tags power Global Search so recruiters and collaborators can filter by the tools they need.

</Step>
<Step>

### Add visuals & links
Upload screenshots and wire up the live URL and repository/demo links.

</Step>
<Step>

### Set the status honestly
**In Progress** projects with regular [build logs](./build-logs) are magnet content — they show trajectory, not just outcomes.

</Step>
</Steps>

## Projects vs. Portfolio vs. Launch

<Accordions>
<Accordion title="Project = the thing, in depth">
Structured data about one product: stack, links, screenshots, logs. Lives on your profile and in search.
</Accordion>
<Accordion title="Portfolio = the curated gallery">
Selected highlights presented for employers/collaborators via portfolio blocks and themes. Lives at your profile's portfolio view.
</Accordion>
<Accordion title="Launch = the moment, in public">
Submitting a product to the weekly Launch leaderboard for upvotes and ranking. A spike of attention that then points back at the project page.
</Accordion>
</Accordions>

The flywheel: **project** holds the details → **build logs** narrate the journey → [Feed posts](../feed) distribute the updates → [Launch](../launch) creates the spike → [portfolio](../profile/portfolio) curates the result.
